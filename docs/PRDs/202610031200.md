i# Agon MCP & Training Plan System — Design Report

## 1. Overview

This document describes the **MCP (Model Context Protocol)** integration and the new **Training Plan** data model added to Agon. Together they enable an AI model (Claude, GPT, etc.) to:

1. **Read** and **analyse** past training sessions (FIT/TCX files already uploaded)
2. **Generate** structured multi-week training plans based on that analysis
3. **Store** the plans persistently in SQLite alongside the existing activity, goal, and schedule data
4. **Act** on the user's behalf — create goals, update the weekly schedule template, manage plan lifecycle

The design follows the project's `stdlib-first` philosophy and extends the existing `http.ServeMux` routing pattern.

## 3. MCP Layer

### 3.1 Protocol (`server/internal/mcp/protocol.go`)

Defines JSON-RPC 2.0 types and MCP-specific types:
- `JSONRPCRequest`, `JSONRPCResponse` — transport envelope
- `MCPResource`, `MCPTool`, `MCPPrompt` — discovery types
- `MCPCallToolResult`, `MCPReadResourceResult` — result types

Supports standard MCP methods: `initialize`, `ping`, `resources/list`, `resources/read`, `tools/list`, `tools/call`.

### 3.2 Resources (read-only data exposure)

Resources expose Agon's training data to the AI via the `agon://` URI scheme:

| URI | Content |
|-----|---------|
| `agon://activities` | All training sessions (ID, name, date, distance, duration, heart rate, elevation) |
| `agon://activities/{id}` | Full detail for one activity including GPS records, HR data, lap info |
| `agon://analytics/summary` | Dashboard summary: totals, weekly/monthly distance, pace/HR trends, training load, personal bests |
| `agon://analytics/weekly-trend?weeks=N` | Weekly distance trend (last N weeks) |
| `agon://analytics/monthly-trend?months=N` | Monthly distance trend (last N months) |
| `agon://analytics/personal-bests` | Personal best records by distance |
| `agon://goals` | Active training goals with progress |
| `agon://schedule/template` | Reusable weekly schedule template |
| `agon://schedule/planned` | Planned sessions by date |
| `agon://training-plans` | All AI-generated training plans |
| `agon://training-plans/{id}` | One training plan with all its sessions |

**Example AI workflow:** Before generating a plan, the AI reads `agon://activities` and `agon://analytics/summary` to understand the user's training status, then reads `agon://goals` and `agon://schedule/template` to understand existing commitments.

### 3.3 Tools (actions the AI can take)

| Tool | What it does |
|------|-------------|
| `generate_training_plan` | Creates a new training plan with title, reasoning, week count, start date, and an array of session definitions |
| `create_goal` | Adds a weekly or monthly distance goal |
| `create_planned_session` | Adds a single planned session on a specific date |
| `update_schedule_template` | Replaces the weekly schedule template (all 7 days) |
| `update_plan_status` | Changes a plan's lifecycle: `draft` → `active` → `archived` |

### 3.4 Provider pattern

- **`AgonResourceProvider`** (`handler.go`): Implements `ResourceProvider` interface, wired to SQLite and storage backends
- **`AgonToolProvider`** (`handler.go`): Implements `ToolProvider` interface, decodes arguments from JSON into typed Go structs before executing

### 3.5 Configuration

#### HTTP mode (recommended, already wired in this repo)

Start the API server (which embeds the MCP server):

```bash
./cmd/agon.sh            # backend (:8080) + frontend (:3000)
# or just the backend:
(cd server && go run ./cmd/api)
```

The MCP endpoint is then live at `http://localhost:8080/api/mcp`.

**VS Code / GitHub Copilot** — `.vscode/mcp.json`:

```json
{
  "servers": {
    "agon-training": {
      "type": "http",
      "url": "http://localhost:8080/api/mcp"
    }
  }
}
```

**Cursor** — `.cursor/mcp.json`: same shape with `"mcpServers": {...}`.

**Claude Code** — registered via CLI (mirrored in repo `.mcp.json`):

```bash
claude mcp add --transport http agon-training http://localhost:8080/api/mcp
# verify: claude mcp list  →  agon-training: ... (HTTP) - ✔ Connected
```

**Claude Desktop** — `~/.config/Claude/claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "agon-training": {
      "type": "http",
      "url": "http://localhost:8080/api/mcp"
    }
  }
}
```

Because the MCP server runs inside the API process, it uses the exact same
SQLite connection as the REST API — no path/env mismatch, no separate binary.
Protocol version negotiation accepts `2024-11-05`, `2025-03-26`, and
`2025-06-18`.

#### stdio mode (fallback)

For clients without HTTP MCP support, `cmd/mcp-run.sh` builds and launches
`server/cmd/mcp` over stdin/stdout. Example Claude Desktop entry:

```json
{
  "mcpServers": {
    "agon-training": {
      "command": "/absolute/path/to/agon/cmd/mcp-run.sh",
      "args": []
    }
  }
}
```

## 4. Training Plan Data Model

### 4.1 Tables

#### `training_plans`

| Column | Type | Description |
|--------|------|-------------|
| `id` | TEXT PK | Auto-generated UUID-like ID |
| `title` | TEXT | Human-readable plan title |
| `description` | TEXT | Purpose and approach description |
| `reasoning` | TEXT | AI's analysis of past training and rationale for the plan |
| `generation_prompt` | TEXT | The AI prompt used to generate |
| `generation_system` | TEXT | System prompt for generation |
| `generation_model` | TEXT | AI model identifier |
| `generation_provider` | TEXT | AI provider name |
| `week_count` | INTEGER | Number of weeks (1–16) |
| `start_date` | TEXT | Plan start date (YYYY-MM-DD) |
| `end_date` | TEXT | Plan end date (computed) |
| `status` | TEXT | `draft` · `active` · `archived` |
| `session_count` | INTEGER | Number of planned sessions |
| `created_at` | TEXT | RFC3339 timestamp |
| `updated_at` | TEXT | RFC3339 timestamp |

#### `training_plan_sessions`

| Column | Type | Description |
|--------|------|-------------|
| `id` | TEXT PK | Auto-generated |
| `plan_id` | TEXT FK → `training_plans(id)` | Parent plan |
| `week_number` | INTEGER | 1-based week number |
| `day_of_week` | INTEGER | 0=Monday … 6=Sunday |
| `date` | TEXT | Concrete date (YYYY-MM-DD) |
| `training_type` | TEXT | run, bike, swim, rest, strength, … |
| `title` | TEXT | Short session title |
| `description` | TEXT | Detailed session instructions |
| `target_distance_meters` | REAL | Target distance |
| `target_duration_seconds` | REAL | Target duration |
| `target_pace_sec_per_km` | REAL | Target pace |
| `target_heart_rate_min` | REAL | Lower HR zone |
| `target_heart_rate_max` | REAL | Upper HR zone |
| `intensity` | TEXT | easy · moderate · hard · recovery |
| `sort_order` | INTEGER | Display ordering within week/day |
| `notes` | TEXT | Coach notes |

### 4.2 CRUD operations

All in `server/internal/trainingplan/store.go`:

| Function | Description |
|----------|-------------|
| `EnsureTables(ctx, db)` | Creates/upgrades SQLite schema |
| `InsertPlan(ctx, db, plan, sessions)` | Creates plan + sessions in a single transaction |
| `ListPlans(ctx, db, statusFilter)` | Lists plans, optionally filtered by status |
| `GetPlan(ctx, db, id)` | Retrieves plan + all sessions |
| `UpdatePlanStatus(ctx, db, id, status)` | Transitions lifecycle (draft→active→archived) |
| `DeletePlan(ctx, db, id)` | Deletes plan and sessions (CASCADE) |

### 4.3 REST API (`/api/training-plans`)

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/training-plans` | List plans (optional `?status=active`) |
| `GET` | `/api/training-plans/{id}` | Get plan with sessions |
| `POST` | `/api/training-plans` | Create a new plan (used for manual creation, or AI-generated) |
| `PUT` | `/api/training-plans/{id}/status` | Update lifecycle status |
| `DELETE` | `/api/training-plans/{id}` | Delete a plan |

## 5. AI-Generated Plan Lifecycle

```
[AI reads past training via resources]
           │
           ▼
[AI calls tools/generate_training_plan]
           │
           ▼
           ┌──────────┐
           │  draft    │ ← just created, needs review
           └────┬─────┘
                │ user reviews & activates
                ▼
           ┌──────────┐
           │  active   │ ← currently followed
           └────┬─────┘
                │ plan superseded or complete
                ▼
           ┌──────────┐
           │ archived  │ ← historical reference
           └──────────┘
```

## 8. Usage Example (AI → MCP — Claude Desktop)

When a user asks _"Generate a 4-week marathon training plan based on my recent training"_, the AI:

1. **Reads** `agon://analytics/summary` — gets total volume, weekly trend, pace/HR trends
2. **Reads** `agon://activities` — identifies the user's typical weekly distance, frequency, recent intensity
3. **Reads** `agon://goals` — sees "40 km per week" goal
4. **Reads** `agon://schedule/template` — sees existing weekly structure
5. **Calls** `tools/generate_training_plan` with:

```json
{
  "title": "Marathon Base Build — 4 Weeks",
  "description": "Progressive overload from 35 km/week to 50 km/week",
  "reasoning": "Past 8 weeks show ~35 km/wk average with Monday/Wednesday/Saturday sessions. HR drift suggests aerobic base is developing. Progression builds conservatively in 10% increments.",
  "weekCount": 4,
  "startDate": "2026-09-14",
  "sessions": [
    {"weekNumber": 1, "dayOfWeek": 1, "trainingType": "run", "title": "Easy Recovery", "targetDistanceMeters": 8000, "intensity": "easy"},
    {"weekNumber": 1, "dayOfWeek": 3, "trainingType": "run", "title": "Tempo", "targetDistanceMeters": 10000, "intensity": "moderate"},
    {"weekNumber": 1, "dayOfWeek": 6, "trainingType": "run", "title": "Long Run", "targetDistanceMeters": 17000, "intensity": "easy"},
    ...
  ]
}
```

6. **Creates goals** via `tools/create_goal` to set appropriate weekly targets
7. **Updates schedule template** via `tools/update_schedule_template` to reflect the new plan

## 9. Future Extensions

- **Frontend UI**: A "Training Plans" tab to browse, activate, archive AI-generated plans
- **Plan comparison**: Side-by-side view of planned vs completed sessions
- **Plan adjustment**: AI re-analysis mid-plan to adjust sessions based on actual completion
- **Multi-discipline plans**: Swim, bike, strength sessions alongside runs
- **Prompt library**: Reusable MCP prompt templates for common training scenarios (base building, race prep, recovery)
